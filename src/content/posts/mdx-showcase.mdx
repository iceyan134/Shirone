MDX 可以把 Markdown 的写作体验和组件能力结合起来。普通文章用 `.md` 就够；当你需要在正文里嵌入交互组件、数据映射或 JSX 表达式时，再使用 `.mdx`。

:::tip
MDX 很强，但也更接近代码。正式写作时建议先用 Markdown，确实需要组件再升级为 MDX。
:::

## Markdown 与 MDX 对比

| 能力 | `.md` | `.mdx` |
| :--- | :--- | :--- |
| 标题、段落、列表 | 支持 | 支持 |
| 代码高亮 | 支持 | 支持 |
| Mermaid / KaTeX | 支持 | 支持 |
| 提示块 | 支持 | 支持 |
| 直接导入组件 | 不支持 | 支持 |
| JSX 表达式 | 不支持 | 支持 |
| 交互岛 | 不支持 | 支持 |

## 适合使用 MDX 的场景

- 在文章里放一个真正的交互控件。
- 把数组数据映射成多张卡片。
- 复用已有 Svelte 组件展示复杂状态。
- 写组件库或主题能力展示文章。

## 基本结构

```mdx
---
title: "MDX 示例"
published: 2026-09-24
---

import Button from "@components/atoms/action/Button.svelte";

正文内容。

<Button label="交互按钮" client:visible />
```

## 注意事项

- 交互组件需要合适的 `client:*` 指令。
- 纯展示组件优先保持 SSR 输出。
- 不要把大量业务逻辑塞进文章里；复杂功能更适合写成组件。
