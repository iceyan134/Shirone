这份速查是写博客时给自己看的。正文用 Markdown，文件保存为 `src/content/posts/文章名.md`；保存后博客会按文章头信息生成页面。需要插入数学公式时看 [LaTeX 公式速查](/posts/latex-math-cheatsheet/)。

## 先写文章头信息

新文章最少需要标题和发布日期，放在文件最上方、两条 `---` 之间：

````yaml
---
title: 一次 NPC1L1 实验记录
published: 2026-09-25
description: 用一句话说明这篇文章写什么。
tags: [NPC1L1, 实验记录]
category: 实验进展
draft: false
---
````

`draft: true` 表示草稿，正式构建时不发布；`pinned: true` 会将文章置顶。`category` 是一个分类名称，`tags` 可以写多个关键词。本博客目前的分类是平铺的，`实验/细胞` 这样的斜杠文本不会自动生成父子分类。需要修改已有文章时，可加 `updated: 2026-09-26`。

## 标题、段落与强调

````md
# 一级标题
## 二级标题
### 三级标题

普通段落之间留一个空行。

**重点**、*轻度强调*、~~删除线~~、`代码或文件名`。
````

文章标题已经在头信息里，正文通常从 `##` 开始。换段落时留空行；行尾直接回车通常仍属于同一段。

## 列表、任务和引用

````md
- 第一项
- 第二项
  - 子项

1. 提出问题
2. 设计对照
3. 记录结果

- [ ] 待完成
- [x] 已完成

> 引用或备注写在这里。
````

实验记录里适合用有序列表写步骤，用任务列表追踪待办。引用块适合标出原文或补充说明；自己的结论最好另起段落，避免和引用混在一起。

## 链接与图片

````md
[查看 NPC1L1 项目入门地图](/posts/npc1l1-project-onboarding/)

![图像内容的简短说明](/images/example.png "图片标题")
````

站内文章用 `/posts/文章名/` 这样的路径。放在 `public/images/example.png` 的图片，对应网页路径是 `/images/example.png`。图片说明要描述图中内容，不要只写“图片 1”。

## 表格与分隔线

````md
| 组别 | 目的 | 结果 |
| --- | --- | --- |
| 对照组 | 建立基线 | 待填写 |
| 处理组 | 比较变化 | 待填写 |

---
````

表格适合概览，不适合塞进长段落或完整原始数据。两行之间的 `---` 可用作分隔线；放在文章开头时，它也是头信息的边界。

## 代码块与转义

行内代码用一对反引号。多行代码用三个反引号包住，开头可以标语言：

````md
```python
print("hello, world")
```
````

如果要显示 Markdown 符号本身，可在前面加反斜杠，例如 `\*不是斜体\*`。如果要让读者复制原始语法，就像本文一样把它放进代码块。

## 博客额外支持的写法

提示框适合放注意事项：

````md
:::tip[记录习惯]
把观察、解释和下一步计划分开写。
:::
````

Mermaid 代码块可以画简单流程图：

````md
```mermaid
flowchart LR
  A[提出问题] --> B[设计实验] --> C[分析结果]
```
````

这些语法在文章中使用时会按需加载。日常写作先用普通 Markdown 就够了；复杂排版应服务于内容，不必为了展示组件而增加文章负担。

## 发布前检查

1. 标题和摘要能否让人一眼知道文章解决什么问题？
2. 图片、表格是否有足够的说明，单位与对照是否写清？
3. 推测有没有写成已证实的结果？
4. 链接是否能打开，草稿状态是否正确？

写实验文章时，建议额外注明日期、样本/批次、原始记录位置和未解决的问题。这样以后自己回看，也能迅速找回当时的依据。
